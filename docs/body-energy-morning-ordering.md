# Qualified Body Morning ordering boundary

This is a local software candidate, not production or physiological acceptance.
Body registration remains `PENDING_GENUINE_EVIDENCE_AND_FINAL_GATE`; publication
and the proposed drop policy retain every original qualification and consent gate.
No provider, real user health record, profile change, deployment or real Telegram
send is performed by the fixtures.

## Existing dependency and new repair

`src/index.js` originally runs DAILY_REPORT before WHOOP_SYNC.
`src/dataSource.js` polling/history does not persist canonical sources. Body
calculation is admitted only in the separate Stage 6 DRAIN after a genuinely
successful whole SYNC and its original HMAC handoff. A prior too-soon wake tick
can naturally prepare Body before the first eligible Morning; the first eligible
tick with new sources can instead send the ordinary report before Body exists.
The daily claim correctly prevents a replacement report after delivery.

For an already qualified Body owner only, `src/bodyEnergyMorningReadiness.js`
may defer **before claim/history/model** until the next existing ten-minute cron
tick. This is a new technical ordering repair derived from the existing cadence,
not a new owner-approved notification clock. It performs no calculation,
canonical ingestion, job completion, handoff or permit reservation. The original
whole SYNC remains downstream; its real outcome independently authorizes DRAIN.
`DAILY_DEFERRED_BODY` and durable `dailyDeferredBody` distinguish a pending report
from successful resource synchronization. They never mean delivered or product
complete.

Waiting requires actual cloudflare SYNC ownership/budget, the original scheduler
window (including the next tick), READY owner, saved profile revision, owned
fresh scored wake/recovery, original accessible/supported inputs, actual adopted
robust baseline maturity, and the original unexpired pilot/remaining attempts.
It also requires a genuinely ready current-generation queue source or proof that
the original normal sleep/recovery/cycle synchronization is due and supported by
the fresh owned poll. A recovery's Cycle identifier supports a forthcoming
original fetch; it does not supply a current strain value or fabricated source.
Original throttling/backoff is never bypassed. Forecast eligibility does not
guarantee future provider success or that calculation finishes before the tick.

An already AVAILABLE Body proceeds normally. Pending/unqualified/default OFF,
STOP, expired/exhausted pilot, unsupported/missing inputs, stale result, denied
forecast, backoff, last scheduler slot or an expired anchor proceeds ordinarily.
Cancellation, deadline, foreign/expired required owner and lifecycle/auth/purge
currentness failures propagate; they do not authorize an ordinary model/send.
If Body remains unavailable on the next tick, the original ordinary report
proceeds once, with honest missing-state output and original claim/delivery fences.

## Durable one-cadence marker

The existing v32 `briefing_evaluations` row has reserved type
`daily_body_readiness`; the generic overwriting evaluation API rejects that type.
A private explicitly named owned transaction conditionally inserts/CAS updates
one row per owner. Its keyed seal binds health date, opaque sleep identity and
wake identity, original observation/deadline, lifecycle/auth/purge/source/input
generations, timezone and durable profile revision. Serialization is checked
against the existing 500-byte limit, never truncated. Original privacy artifact
identity and TENANT_LEGACY dependency links make the marker subject to existing
all-report-type physical redaction.

Same health date or sleep/wake identity cannot renew the deadline. Corrected
source generation, profile/locale/timezone/lifecycle/auth ABA never resets the
anchor. Only a later health date with a different owned sleep identity and later
wake can replace a valid old marker. Malformed, purged or unverifiable markers
fail closed to ordinary service, never to a forged new wait. Same-execution
receipt replay does not issue a second wait; a fresh legitimate owner can only
read the original still-unexpired anchor.

Body's existing generic profile getter initializes its revision in a write
transaction, which is unsuitable inside owned report execution. The Body
consumer uses `profileRevision(...,{initialize:false})` in an owned READONLY
transaction there. Missing/malformed revision omits optional Body without
initializing Settings authority or poisoning `execution.workRejected`. Generic
Settings/getProfileRevision and ordinary `/energy` remain unchanged.

## Verification and limits

Run on Node 22:

```sh
node --expose-gc --test --test-concurrency=1 test/body-morning-order.test.js
```

Scenarios isolate the original strict empty-filename memory fixture in child
Node processes because the installed native receiver can retain a handle after
close. Positive calendar tests substitute only the Taipei hour/minute formatter;
Node/SQLite clocks, source capture, ownership/leases and local COMMIT ACKs remain
actual. The protocol compatibility fixture has no Body grant or health records.

The positive chain uses actual canonical SYNC and FAST reconciliation, original
HMAC handoff, separate actually committed/finalized PARTIAL DRAIN source unit,
then a second owned Morning with actual typed Body reader and one synthetic
Telegram ACK/durable delivery. Whole-generation/family jobs remain incomplete.
Negative controls cover original deadline/restart, malformed/missing revision,
provider ownership/time/duplicates/missingness, STOP/pilot expiry/exhaustion,
parent cancellation during availability and marker write, and fresh owner,
lifecycle/auth/purge/deadline invalidation before any model/send/claim.
Exact old 207/16dc decoders validate the original raw result digest, ignore the
new sanitized count and preserve cached handoff/finalization and authoritative
DB rows. The unchanged Worker continues its original response/handoff behavior.

These are synthetic software proofs. They do not grant empirical qualification,
real score publication, natural alert observation, provider operating capacity,
all-user stabilization or Stage 7 readiness. Existing Source/DRAIN operating
qualification and all clinical/product gates remain separate.
