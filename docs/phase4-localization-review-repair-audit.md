# Phase 4 localization review repair: user-facing literal audit

Scope: all 210 JavaScript files under `src` as of this repair. Search covered Han and Vietnamese text, quoted English outbound copy, direct Telegram `send`/`notifyError` paths, headings, errors, status, coach, briefing, proactive, account, and onboarding paths. Each candidate was traced to its caller and classified below. A catalog key is required before rendering any ordinary user message.

| Class | Paths and disposition |
| --- | --- |
| A — ordinary user output | `bot/answer`, `bot/commands`, `briefingStatus`, `dataQuality`, `evidence`, `healthspanEngine`, `usage`, `assertionRenderer`, `journal`, `questionEngine`, `proactiveMessages`, `proactiveReanalysis`, `guardian`, `bot/experimentFlow`, `bot/conversation`, `bot/healthEducation`, `narrativePlan`, `format`, `onboarding`, `whoopOAuthCallback`: use `t(locale, key, namedValues)` and the merged catalog. The preselection selector and preselection errors compose all three catalog translations. Cost groups and permission names are translated before interpolation. |
| A — operational destination | `maintenance`, `schedulerWatchdog`, and global `telegram.notifyError`: use `admin.*` catalog keys. This destination has no per-user locale and retains the existing system language per call. Per-user error notices use the recipient locale. |
| B — internal data or diagnostics | Logger calls, exception messages, parser aliases and regular expressions, policy candidate keys, capability/healthspan descriptions, analytics notes, and persisted insight/evidence statement fields. These fields are not rendered directly by the Telegram or OAuth presentation paths; the reader resolves approved keys and facts. The `proactiveReanalysis` persisted statement is internal; follow-up publication now renders `proactive.associationStatement` for every locale. |
| C — model instruction/data | `bot/answer` trusted-facts context, `bot/intent` classification prompt, `bot/router` journal parser prompt, `coach` instructions, `journalFoundationValidation` parser instruction, and publish guard detection labels. They are supplied to model or validation code, not directly sent as reply text. Publication still passes through deterministic message rendering and guards. |

All alternative Traditional Chinese renderer branches in the user-facing functions above were removed. The sole remaining `locale === 'zh-TW'` outside `localization.js` sets the HTML `lang` attribute in `whoopOAuthCallback`; it selects no copy. Locale-specific punctuation for narrative lists is a catalog key. Source-wide static checks remain targeted to known renderer functions so internal prompts and parsing vocabulary do not create false positives.

The catalog merge rejects any duplicate key, including identical text. The dedicated repair test checks duplicate conflicts, key and placeholder parity, unsupported locales, validation-code suppression, and the absence of alternate Traditional Chinese renderer branches. Existing integration tests cover onboarding, six-user reverse-order/restart isolation, briefing, coach, episodes, insights, associations, and Public Beta presentation.
