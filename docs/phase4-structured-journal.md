# Structured Journal foundation (default off)

This is persistence and deterministic validation, not a production cutover. No production entry point constructs the Journal control adapter or the LIVE answer authority. The ordinary factory cannot issue LIVE contexts; the isolated fixture owns and verifies its actual in-memory database. No new scheduler, dispatcher, proactive selection policy, model call, WHOOP call, typing or Telegram send is present.

## Source and parser boundaries

`journal.create/correct/remove/realign` require a separately branded authenticated source controller, not a SHADOW computation context. Logical/source/revision identities are tenant-qualified keyed hashes. Source replay returns the existing opaque identity before candidate evaluation. Logical deletion removes every revision and retains only the ADR tombstone; replay cannot resurrect it.

`journalFoundationValidation.js` is the closed, deterministic candidate boundary. It reuses the existing category registry, requires finite typed values and known units, explicit polarity, confidence at least 0.75, bounded source-backed Unicode excerpts, and unambiguous exact time evidence. Missing or ambiguous facts return REJECT or REQUIRE_CLARIFICATION without writes. User/model objects cannot supply ownership, authority, question IDs, health dates, execution mode, destinations, flags, tool arguments or send capabilities. The parser-input helper separates fixed instructions from untrusted data and calls no model.

Every accepted fact carries parser, normalizer and alignment versions. The taxonomy is `journal-taxonomy-v1`, encoded by `journal-normalizer-v1` and the source assertion relationship; the factor registry is `journal-factors-v1`. Relevant current owned main-wake alignment takes precedence over the existing 04:00 fallback. Late sleep/timezone realignment is a new revision, not an in-place history rewrite. UNKNOWN is never stored as a negative fact.

## Exposure and coverage

Queries use ACTIVE, unredacted, completely linked own sources. A positive covering fact proves EXPOSED. Only a whole-window explicit negative or versioned confirmed coverage proves CONFIRMED_UNEXPOSED. Missing/unrelated/partial negative evidence is UNKNOWN. Contradictory positive/negative proofs are explicitly flagged. The deterministic eligibility helper excludes UNKNOWN from comparison groups, uses all eligible observations for its unknown fraction, and persists method/threshold versions in its returned manifest. At exactly 0.50 it passes only that one gate; it never promotes an insight.

Coverage creation is private to accepted answers to an occupied LIVE `journal-coverage-v1` question with a registered explicit factor set, exact displayed interval and utility score meeting its positive threshold. The pack supplies no policy that chooses these questions and never asks mechanically. SHADOW only stores normalized synthetic answer content. Correction can narrow the factor set, not silently add unlisted factors; changed window bounds require explicit source-text evidence. Correction redacts the prior coverage and dependent copies, creates the next revision, and reclassifies through full invalidation. Deletion leaves health content null and prevents old-source replay.

## Answers and interaction slots

`journalAnswers.accept` replaces the earlier raw JSON slot-answer primitive. It requires a standalone operation, the exact current own question/slot revision and explicit request reference, a current answer window, lifecycle/auth/privacy fences, deterministic normalization, and a durable private inbound claim/lane proof for LIVE. Replay lookup precedes candidate parsing and slot routing. Rejected/ambiguous candidates cannot resolve a slot.

The old-generation question is verified in a completed read transaction, then its exact snapshot and fences are rechecked under the answer write lock. LIVE commits the new shared assertion, fixed non-sendable receipt, source/input generation, same-mode answer event and matching slot/pending transition atomically. A new answer event records the resulting input generation. SHADOW writes no real Journal, coverage, Telegram receipt, pending row, or delivery attempt.

`ANSWER_LINEAGE` is a narrowly validated answer-to-question protocol edge, not permission to reuse old numerical evidence: its own tenant/mode/question identity and lifecycle/auth remain checked, and it remains in the purge graph. General numeric-parent generation checks are unchanged. Corrected accepted answers get the next opaque answer revision with their own newly validated assertion and durable correction-command receipt; old question/event IDs retain protocol lineage without reconstructing erased dependency edges. Controller-origin correction uses its authenticated T0 ledger as the source receipt and never fabricates a Telegram update. Equivalent wording/confidence/parser-only changes reuse the current answer event. Corrections/deletions never resolve a different occupied slot, reopen a terminal slot, select a follow-up, or send anything.

## T0 / T1 / T2 and inbound adapter

`phase4JournalInbound.route` is an optional, default-null hook after existing private identity/processing-lease/lane validation and before `processTelegramOperation`, typing or ordinary routing. No production caller supplies it. Its deterministic synthetic control grammar is `/journal_delete <logical ID>` or `/journal_correct <logical ID> <expected revision> <JSON containing candidate and sourceText only>`; all candidates still pass the closed validator. Existing ADMITTED ledger lookup precedes even command parsing after a crash.

T0 is always independently committed. It stages only the validated new assertion with explicit source provenance, increments the fence once, and rejects a competing ADMITTED command for the same subject. T1 redacts the complete transitive closure across both modes and conservative legacy copies, removes reconstructive links, applies exact sentinels/range privacy, preserves independent assertions/unrelated sources and transport truth, writes replacement content and the origin's fixed non-health receipt atomically, then deletes staging. It cannot send. T2 verifies DB/edge/staging postconditions and old-cache acknowledgments before decrementing the fence exactly once.

T1 rollback leaves T0 intact; retries use durable staged state, not the original parser/handler. An expired (30-day maximum) replacement is destroyed in an independently committed cleanup, never restored by failed T1 rollback; the fence remains. `journal.resumeCorrection` accepts only a fresh authenticated, deterministic same-subject replacement under that original fence. This is a callable foundation, not a background retention worker. Correction after an authorization change fails closed until explicitly revalidated; there is no automatic stale-authority recovery. A later physical deletion may complete before an earlier correction's T2 only when durable target/ledger proof establishes the later removal.

The existing global redacted receipt replay still returns exactly `{"reply":null,"redacted":true,"reason":"HEALTH_CONTENT_REDACTED"}` before identity/router/Q&A/model/mutation/send. Dedicated control replay returns no sendable reply even after T2. Coverage/Journal deletion makes unproven days UNKNOWN and cannot delete independent WHOOP records or unrelated Journal/experiment assertions.
