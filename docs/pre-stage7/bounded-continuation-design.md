# R1 bounded continuation architecture candidate

**Final R1 disposition: EXECUTION_BUDGET_UNRESOLVED.** The safety repairs and architecture proposal are reviewable; a convergent unattended completion model is not implemented or proven. Public Beta promotion is blocked.

The full synchronous path has thousands of protected HTTP observations. Neither warm fixtures nor an enlarged timeout establish a 120-second completion guarantee. The candidate preserves 120s Cloudflare SYNC work, 30s admission, 15s cleanup, nominal 165s whole server authority, 180s Worker SYNC caller, 100s DRAIN caller, 45s Cloudflare DRAIN work, 225s minimum phase lease and tenant work lease +15s. Worker fixed total window remains 561s; no timer has increased.

Implemented locally: budget/cancellation and tenant contention yield an explicit resumable response; ESTABLISHED receipts/identity survive; temporary contention cannot finalize failure; signed endpoint evicts resumable in-memory results; Worker honors bounded retryAfterMs and reuses identical body/request identity within its original bounded attempts. COMMIT_INDETERMINATE remains 503 and is never reported as definite rollback or success. WORK_COMMITTED reconciles immutable result before finalization. An acknowledged durable work COMMIT followed by finalization authority loss is explicitly WORK_COMMITTED_UNFINALIZED/202; this observation grants no new authority. Phase completion cancels nested child work before disposing its timers, including successful completion before the nominal deadline. Finalized replay and request conflict remain distinct. An expired durable predecessor deadline permits same-request CAS lease shortening/takeover in a serialized transaction, never on mere caller disconnect. Production continuation observation time defaults to original created_at; explicit fixture clocks are not HTTP inputs.

## Required durable continuation contract

Before rollout of an async model, independently review a persistent dispatcher using the EXISTING v32 phase4_executions canonical_request_json, identity, scope, owner, generation, lease/deadline and receipt tables. Discovery must be authenticated, read-only, bounded and release/config/source/mode restricted. It must return only opaque canonical transport identity, progress category and next eligible time; no tenant or health data. Select an existing resumable identity before creating a new same-scope request. Each continuation needs fresh authorized invocation/admission; persistence never grants authority. Enforce one dispatcher/scope via atomic existing resource_locks and validate DB time. A Worker death must not lose identity, so recovery cannot depend on an ephemeral random root or eventual-consistency KV alone.

States: INCOMPLETE_RESUMABLE; COORDINATION_PENDING; COMMIT_UNCERTAIN; WORK_COMMITTED_UNFINALIZED; FINALIZED_SUCCESS; TERMINAL_FAILURE; STALE_REQUEST; IDENTITY_CONFLICT. Pending states never grant handoff or presentation. Finalized result is immutable. Different body with same ID is rejected. Original release/config/source/mode cannot change. New-release dispatch cannot adopt an obsolete identity. Retain committed receipts forever under existing v32 invariants.

For reliable slow-path convergence, durable semantic checkpoints must bound each resource/window/provider operation, reconciliation slice and derived-output pass. A checkpoint records only approved scalar/count/hash receipt results, commits atomically with its effect where possible, and advances only after actual completion. Retry reobserves tenant lifecycle/auth/purge/currentness before accepting a prior checkpoint. Metadata leases are acquired afresh under new ownership; replaying an old lease-acquisition receipt is not a new grant. No business transaction spans an external provider wait. Uncertain provider operations need existing token/delivery ambiguity semantics; never repeat a Telegram send after ambiguity.

Fix observation time and resource window identity across continuation. Bound continuation age (proposed 15 minutes, matching handoff TTL); older incomplete work is a distinct stale outcome requiring explicit reconciliation rather than a new-date brief under an old ID. Finalized replay remains read-only. WORK_COMMITTED must still reconcile truthful durable outcome even when stale.

## Acceptance before architectural approval

A–H HTTP/Hrana rehearsals including 112ms and adversarial latency must demonstrate bounded individual segments, durable monotonic progress and convergence; no false COMPLETE, lost receipts, stale owner mutations or duplicate committed WHOOP/Stage6 effects/sends. Include death before first business receipt, delayed COMMIT, mixed tenant leases, midnight, dispatcher death and unchanged current release gates. If the experiment cannot converge, report EXECUTION_BUDGET_UNRESOLVED; do not approve rollout from a specification or a 202 response alone.

Architecture owner must approve dispatcher authority, age limit, checkpoint boundaries, secret isolation, restart discovery and rollback before deployment. This document is a concrete review proposal, not implementation or production approval for persistent dispatch.

An independent process resumed the preserved same-request ledger from 82 to 159 receipts, still pending. The final safety containment bounds new incomplete work to 15 minutes from immutable created_at, using database time at admission and clamping the durable/child deadlines. Stale requests return 410 before takeover or provider work; already committed receipts remain. Acknowledged WORK_COMMITTED can still finalize immutable metadata without new business work, but late SYNC finalization grants no renewed drain token. Receipt-backed partial DRAIN retains the existing authenticated metadata-only PARTIAL reconciliation path. Finalized replay remains immutable, including after parent expiry. No new schema object/version was introduced.

## Required checkpoint decision

A whole-user `completed=true` cache is insufficient: lifecycle/auth/purge/input generation, source-window state, eligibility, locale, recipient and local calendar can change between completion and finalization. It must not bypass currentness/privacy revalidation. Select bounded resource and reconciliation slices; record only approved scalar/HMAC completion receipts in existing v32 storage, atomically with their effect, with no external wait inside a transaction. Bind request/release/source/config/mode, original semantic window, tenant lifecycle/auth/purge/input generation and resource version. Acquire a fresh tenant lease under every authorized owner; no receipt grants ownership.

Before skipping a completed slice, revalidate all its dependencies. Before finalizing aggregate success, atomically verify the selected cohort/eligibility and all current completion certificates with the phase result, rather than trusting a stale boolean. Reconcile unknown COMMITs through serialized authoritative reads. Permit expired-context reconciliation only for known immutable work or the existing explicit partial-drain contract; never infer COMPLETE from a count of partial receipts. Define local-midnight and scope-age cutoffs so resumed historical work cannot send a stale daily report. Reject stale contexts without erasing their receipts.

Persistent authenticated discovery/dispatch must prioritize a valid existing identity before inventing another one, survive Worker/process death and honor provider, work, whole-phase and age limits independently. It must prove convergence at 112ms/request and adverse jitter/load for three READY users with actual HTTP/Hrana and zero duplicate sends/business effects. These are explicit remaining engineering/architecture gates, not a claim that a 202 response closes R1.
